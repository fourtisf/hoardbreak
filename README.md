# HOARDBREAK

*Rob the dragon. Don't wake it. Be the exit liquidity.*

A mobile-first extraction-heist roguelite. One lair a day, generated from a
`date:depth` seed — the same lair for every player on earth — and a leaderboard
for the biggest single heist.

This repository is the production build of `HOARDBREAK_v0.2.html`, following
`HOARDBREAK_HANDOFF.md`. Both files sit in the repo root and remain the source
of truth for game feel: **the prototype wins any disagreement.**

## What changed from the prototype, and why

The handoff is explicit that game feel, constants and formulas are ported, not
redesigned. The **port** made exactly four structural changes, all required by
§4–§6 and none of which touch game feel. (The separately approved design
changes are in [v0.3 — design changes](#v03--design-changes) below.)

1. **Fixed 60 Hz timestep.** `step()` always advances by `SIM_DT`; the renderer
   interpolates positions by the leftover. The prototype simulated on the rAF
   delta, which makes two machines produce two different runs from one seed —
   replay verification (Phase 4) would be impossible.
2. **Two seeded RNG streams per run.** `rngGen` drives lair layout (must match
   the server); `rngSim` replaces every `Math.random()` inside the simulation,
   including the shrine's relic pick. Cosmetic-only randomness — the landing
   page's drifting motes, screen shake — still uses `Math.random`.
3. **`setTimeout` became `state.timers`.** The telegraphed dragon breath and the
   slain-wyrm fanfare were wall-clock callbacks; they are now scheduled on the
   run so a replay reproduces them.
4. **The simulation no longer touches meta, the DOM or audio.** A run reports a
   `RunResult` and the meta layer applies it (`applyRunResult`). Sound cues and
   whisper lines are emitted into `state.out` for the host to drain. In Phase 2
   `applyRunResult` moves behind `POST /runs/complete` unchanged.

Everything else — the lair generator's draw order, guard and squad AI, the wake
economy, the staged dragon, item effects, compass UX, every tutorial and whisper
string — is a line-by-line port. The parity test is what keeps it honest.

### Deliberately deferred

- Seeds are still computed client-side (`hashStr(date:depth)`), exactly as the
  prototype did. Phase 2 swaps three lines in `apps/web/components/Raid.tsx` for
  `POST /runs/start`.
- The hideout lives in memory for the length of a session and resets on reload
  (§12: "local meta in memory").
- `/board` shows the prototype's seeded stand-in rivals. Phase 2 wires it to the
  Redis ZSET.
- `packages/shared/src/schemas.ts` already pins the API and event/input-log
  shapes so Phase 4's replay worker needs no client change (§6).

## v0.3 — design changes

Handoff §2 says port, do not redesign, and §14 leaves the open questions to
ALFA. These changes were raised as problems, reviewed, and explicitly approved
before being built. They are listed here so the diff against the prototype is
never a surprise.

**Lair generation is untouched by all of them.** Given the same modifier, this
engine still produces byte-identical lairs to `HOARDBREAK_v0.2.html`
(`test/parity.test.ts`), because that determinism is what bounds a submitted
score in §6.

### 1 · You choose which depth to raid

`meta.depth` only ever went up, one per clear, so two players were almost never
in the same lair — which quietly falsified the product's own hook, *"the same
lair for every player on earth"*. Handoff §6 already anticipated the fix
(`POST /runs/start` validates `depth ≤ unlocked`); the prototype simply never
shipped the picker.

Any depth from 1 up to `best + 1` is now selectable in the hideout, with each
night's modifier shown on the button.

**Phase 2 impact:** the board is now keyed by depth as well as date — a single
global "biggest heist" board only ranks who is deepest, since the hoard alone
scales `800 + 420 × depth`. Redis becomes `lb:{date}:{depth}`, which **amends
handoff §8**. `zDailyResponse` already reflects the new shape.

### 2 · The shrine offers a choice

One random relic per run meant a run contained no build decision at all. The
shrine now lays two out and the crew walks into the one it wants; the other
crumbles. Diegetic, no modal, no pause — the same "stand near the thing"
language as chests and prisons. Owning four already? The fifth is handed over
directly: a choice of one is not a choice.

Adds a `RELIC` event code to the §6 log.

### 3 · Relics are visible for the whole run

They were granted in a three-second banner and then invisible, so thirty
seconds later a player could not tell whether they had Lockbreaker or Muffled
Boots — both of which change how you should play. There is now a RELICS row in
the side panel.

### 4 · Nobody spawns inside the extraction zone

The exit strip is `x = 2,3` and the prototype spawned the crew at `x = 3,4,5`,
so two of the four starting thieves began *inside* the zone and EXTRACT was
already lit at "2/4 at exit". Pressing it lost half the crew permanently before
the player had done anything. Spawn starts at `x = 4` now, and the button reads
**EXTRACT — LEAVE 3 BEHIND** in red when it would strand anyone.

### 5 · Creep — stealth is a mechanic, not a timer

Passive wake of 0.9/s gave every run a hard ~111-second ceiling no matter how
well it was played, and there was no way to *play quieter*. Hold Shift (or tap
CREEP on touch) and the crew moves at 0.55×, makes 0.45× the passive noise, and
is spotted at 0.6× the radius.

It is a trade, not a freebie: the same route creeping is ~0.82× the noise but
takes 1.8× as long. Proximity, siphon and combat noise are deliberately
untouched, so the hoard is exactly as dangerous as it always was.

### 6 · Classes pick their targets differently

Every class swung at whatever was nearest, so a five-class roster read as five
stat blocks. Target selection now expresses each fantasy — the Hexer amps the
biggest thing in the room, the Emberkin spreads ignite instead of stacking it,
the Bruiser body-blocks the hardest hitter — with a stickiness bonus so nobody
ping-pongs between two targets. No new abilities, no new buttons.

### 7 · A wiped hideout can never be a dead save

Lose the whole crew with under 60 gold and the prototype was over: RAID
disables at zero crew and raiding is the only income. In Phase 1 a refresh hid
it; once §7 puts the roster in Postgres it is a dead account. If the roster is
empty and you cannot afford the cheapest thief, the guild fronts you one. It
cannot be farmed — you have to have lost everyone to qualify.

### 8 · Pause and abandon

Esc pauses (the sim stops, so it costs no wake). Abandoning ends the run as a
failure that **also costs the crew** — identical to a wipe. That is deliberate:
a free abandon would be a free scouting trip on a daily lair everyone gets one
shot at. What it buys is the two minutes, not the consequences.

### 9 · Three more nights

`MODS` went 5 → 8: A HUNGRY WYRM (sleeps deeper, burns hotter), PLUNDER SEASON
(the gold is in the vaults), SILENT HALLS (blind guards, leaner hoard). All
three reuse existing generator knobs, so the generator itself is unchanged.

This does change which modifier a given date rolls, which is why
`parity.test.ts` pins the modifier from the fixture rather than deriving it.

### 10 · Accessibility

`prefers-reduced-motion` now suppresses screen shake, the banner flash and the
wake vignette, and `--dim` was lifted from a 4.2:1 contrast ratio to clear the
4.5:1 floor.

### Still open — ALFA's call (§14)

Week-2 retention needs a meta-progression arc, and that is a product decision,
not a code one. The depth picker, per-depth personal bests and the wider
modifier rotation help, but a prestige loop or a real unlock ladder is still
§14.4 and still unanswered.

## Notes for Phase 2

- `maxLootFor(run)` in `packages/engine/src/gen.ts` is the validation tier-2
  ceiling, and it lives next to the generator so the two cannot drift apart. It
  already accounts for the two reinforcements stage 2 spawns.
- `RunResult.crewOps` is an ordered replay of roster changes. Apply it in order
  and the lost queue behaves exactly as it did in the prototype, including the
  case where a rescue frees a slot that a later death then fills.
- `RunState.events` is the compact `[t, code, value]` log from §6, already
  emitted for every scoring event.
- The engine's `.js` import specifiers resolve to `.ts` on disk. Vite/vitest does
  this by default; webpack needs the `extensionAlias` in
  `apps/web/next.config.mjs`, and a Fastify app will need the same from `tsx`
  or `tsup`.
